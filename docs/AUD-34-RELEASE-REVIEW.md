## Recovery and MFA support procedure

On a failed deletion, keep the user signed in unless Auth has already disappeared. Retry only after fresh authentication/password verification; resolve uncertain commit status through trusted Auth and owned database checks. Never tell the user all retained copies were removed. Do not repair an account by recreating its application user or restoring a backup blindly.

Before any backup restore becomes accessible, reconcile deletions from an independent record that is not rolled back with that backup; remove application rows, Auth identities/sessions and owned generated audio again. The implementation has **no such independent deletion ledger**. A restore without it may resurrect a deleted account. Recovery must stay offline until reconciled and verified.

MFA support must verify the account owner through a supported MFA challenge/session and fresh authentication before using trusted cleanup. Do not ask users to disable MFA, send passwords/recovery codes, or accept email possession alone as a bypass. No support service-level promise or implemented support endpoint is claimed. The existing product contact provides a request route, not verified operational readiness.
