# AUD-67 completion-flow investigation

Baseline: production merge `4e596bc` (PR #48). Work is isolated from the existing dirty checkout. Linear did not contain AUD-67; its allocator created AUD-66 for this request.

## Flow traced

The server commits the final assessment and lesson closing before `COMPLETED`. `Product.structuredLesson` refreshes saved stats, stores the completion ID and enters `LessonCelebration`. That component owns the one-shot Rive presentation, reduced-motion path, failure fallback, Continue button and 15-second safety timer. Its completion reveals the saved results and optional planning check-in. The lesson-scoped topic offer is claimed transactionally in `app/storage/planner.py`; spoken/typed answers persist roadmap feedback through `app/planner_api.py`. Homework loads its saved per-lesson assignment and can speak an invitation, record a decision, poll discovery and speak confirmation. Previously all these optional paths could finish the entire wrap-up. Return Home is the actual route exit; homework disappearing was also possible without any route change.

## Confirmed findings

1. **Redundant static success presentation.** The completed `SessionShell` mapped idle speech to `Success`, whose state label is “Nice work.” It rendered the original SVG mascot; after closing `Product` explicitly supplied another static success pose. PR #48 inserted the Rive celebration before this existing shell without removing that presentation. Results were hidden until optional wrap-up finished. The patch shows results immediately, removes idle completion presence and retains the mascot only during active tutor voice/recording/thinking. The Rive asset and its runtime are unchanged.
2. **Homework vanished through presentation state, not a router redirect.** `AssignmentCard.startVoice`, polling/recovery, request failures and decision finalizers called `onFinished`; `Product` connected that directly to `finishWrapup`. Closing audio ending (or its timeout) set `wrapupFinished`, and `AssignmentCard` returned `null` whenever `finished && !item.content`. A skipped card therefore appeared, then disappeared. The browser baseline reproduced this. The patch disconnects assignment settlement from closing, adds explicit Finish lesson, retains saved cards and scopes closing cleanup to its own operation/timer. Return Home remains explicit.
3. **Typed preference clicks could be lost.** The focus-only CSS rule resized the mascot area when the text field blurred, moving Send during the pointer gesture. The new preference test initially made zero answer requests; stabilizing the layout while an input exists and retaining interaction layout during the topic step made the same double-click submit exactly once. This can leave the learner seeing the same unanswered interface despite attempting submission.
4. **Completion presentation was reinitializable.** Every `COMPLETED` response reset topic/homework flags and started another celebration. It had no per-lesson consumption guard. The patch consumes presentation by lesson ID, makes topic completion idempotent, unmounts the topic component as soon as it finishes, and prevents concurrent Speak/Keep/typed answers. Restoring completion goes straight to saved results/homework without re-offering or speaking preferences.

The static shell, homework auto-finish wiring and focus resize existed before PR #48 (`42f2939`/earlier). PR #48 made the old static presentation a second celebration; it did not introduce the topic component or homework callbacks. The exact three full preference-screen entries reported on the physical iPhone have **not** been reproduced. No evidence establishes that three backend offers occurred. Transactional claims already prevent that, and accepted feedback already persists. Duplicate completion injection and remount tests now verify that even an incorrectly repeated offer response cannot reopen an answered topic step for the same lesson.
